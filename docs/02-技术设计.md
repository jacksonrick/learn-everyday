## 3. 数据库设计

约定：所有表 `id INTEGER PRIMARY KEY AUTOINCREMENT`，时间统一 UTC ISO 字符串；软删除用 `enabled`；`date` 字段为本地日期 `YYYY-MM-DD`。

### 3.1 基础

**grade 年级**（可扩展，支持中小学）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | |
| name | str(20) | 一年级…六年级 / 初一…高三 |
| stage | str(10) | 小学 / 初中 / 高中 |

预置且**只读**：小学一年级~六年级、初一~初三，共 9 个；不设高中，也不提供增删改接口（`GET /admin/grades` 只用于下拉框）。启动时 `seed._seed_grades()` 会补齐缺失年级、删掉多余年级（含旧库的高中）并清掉其引用。

**child 孩子**
`id, name, gender(male/female), birthday(date), grade_id FK, term(上/下), avatar(emoji), created_at`

**admin_user**：`id, username, password_hash, created_at, last_login_at`
**setting**：`key PK, value(JSON文本), updated_at`

### 3.2 题库

**chinese_char 识字**
`id, char(1..2), pinyin, radical, strokes, structure, words_json(数组), sentence, is_key, level, audio_url, created_at`

**poem 古诗**
`id, title, author, dynasty, genre(诗/词/文言文/蒙学), content(整首,\n分句), pinyin_json, translation, notes, appreciation, level, audio_url, created_at`

**english_word 单词**
`id, word, phonetic, pos, meaning, example, example_cn, kind(单词/短语), level, audio_url, created_at`

**english_sentence 句子**
`id, en, cn, key_words, phonetic_tip, level, audio_url, created_at`

**english_phoneme 音标**
`id, symbol, type(vowel/consonant), category(短元音/长元音/双元音/爆破音…), examples_json, mouth_tip, audio_url, created_at`

**math_rule 出题规则**
`id, name, generator, grade_id, term, topic, params_json, level, created_at`
`generator` 对应 `mathgen.GENERATORS` 注册表键名，如 `mul_multi_digit_by_1`。

**math_question 数学题（人工题/应用题）**
`id, grade_id, term, topic, type(application/choice), stem, answer, unit, options_json, solution, level, created_at`

> `level`（难度等级）= 容易 / 较易 / 中等 / 较难 / 困难，五张题库表 + 出题规则都有这个字段，
> 出题时按 20% / 30% / 30% / 15% / 5% 抽取，见 `services/level.py`。音标库不设等级（48 个固定音标不分难易）。

### 3.3 学习过程

**daily_task 每日任务实例** `unique(child_id, date, subject)`
`id, child_id, date, subject(chinese/math/english), status(pending/doing/done), payload_json(题目与答案), score, total, correct, duration_sec, completed_at, created_at`

**study_record 作答流水**
`id, child_id, date, subject, task_id, item_type, item_id, stem, user_answer, correct_answer, is_correct, duration_ms, created_at`

**checkin 打卡** `unique(child_id, date)`
`id, child_id, date, status(full/partial), subjects_json, points, streak, is_makeup, created_at`

**srs_item 复习调度** `unique(child_id, subject, item_type, item_id)`
`id, child_id, subject, item_type, item_id, stage(0-5), next_date, wrong_count, updated_at`

**wrong_item 错题本** `unique(child_id, subject, item_type, item_id)`
`id, child_id, subject, item_type, item_id, ref_text, snapshot_json, wrong_count, correct_streak, mastered, last_wrong_at`

> `item_id` 一律是**题库主键**（汉字 / 单词 / 古诗 / 应用题 id），不是当天题目序号。数学计算题没有主键，用 `md5(kind + topic)` 生成稳定编号，同一知识点归并成一条错题。`snapshot_json` 存整道题的快照（题干、选项、答案、单位等），重练时直接还原，不用回题库拼装。

### 3.4 积分与奖励

**points_ledger**：`id, child_id, delta, reason, ref_type, ref_id, balance_after, note, created_at`（只增不改，冲正写反向流水）
**reward**：`id, name, cost, icon, stock(-1 无限), child_id(空=通用), created_at`
**redemption**：`id, child_id, reward_id, cost, status(pending/approved/rejected), note, created_at, handled_at`

## 4. API 规范

- 前缀 `/api/v1`，`Content-Type: application/json`
- 统一响应：`{ "ok": true, "data": ... }` / `{ "ok": false, "error": { "code": "...", "message": "..." } }`
- 分页：`?page=1&page_size=20` → `{ items, total, page, page_size }`
- 鉴权：后台 `Authorization: Bearer <jwt>`；客户端靠 `child_id`（家庭内网，无敏感数据，不设防越权）
- 时间：`date` 为 `YYYY-MM-DD`，其余 ISO8601
- 错误码：`AUTH_REQUIRED / AUTH_FAILED / NOT_FOUND / VALIDATION_ERROR / CONFLICT / INTERNAL`

## 5. 核心业务逻辑

### 5.1 每日任务生成（`taskgen.py`）

1. 取孩子的 `grade_id + term` 与 `settings`。
2. **语文（固定）**：认读卡 5 字（全库未学优先，按等级 20/30/30/15/5 分配）+ 组词题 5 道（全库随机，跳过当天认读过的字）+ 古诗 1 首（到期优先，否则按等级加权随机）。
3. **数学**：按 `math_rule`（年级 + 学期匹配）按等级配额抽题组，共 20 题（某档规则不够时从其它档补）；答案随题存库。
4. **英语**：单词朗读 `english_word_read`（默认 10，不够就用学过的补满；题库太小先给选择题留 4 个词）+ 音标朗读 2 + 看中文选英文 2 + 看英文选中文 2 + 音标选词 2 + 组句 1（音标/句子两个开关可整段关掉）。朗读过的词不再出词义题，朗读过的音标不再出音标题。
5. **错题重练**：固定 2 道插在最前面。
6. 组装 payload 写入 `daily_task`，状态 `doing`。同日重复调用直接返回已有 payload（幂等）。
7. **不计分题型**：`poem`（`NO_SCORE_KINDS`）与 `word_read / phoneme_read / char_read`（`NO_SCORE_TYPES`）只记完成、不进 `total`；朗读卡点「下一个」提交 `__read__`，`submit` 写一条「已朗读 / 已认读」记录 + 一条 SRS（否则第二天又被当新内容重发）。

### 5.2 判分（`grading.py`）

| 题型 | 判定 |
|---|---|
| `pinyin_choice` / `choice` | 字符串相等（去空格、统一大小写） |
| `fill_blank`（古诗挖空） | 逐空比较汉字，忽略标点 |
| `order`（英语排序） | 拼接后与答案规范化比较 |
| `fill`（数学） | 数值比较（Decimal），单位可忽略；分数/小数做等值判断 |

提交后：写 `study_record` → 更新 `daily_task`（score/correct/status）→ 更新 `srs_item` → 错题写 `wrong_item` → 触发积分与打卡 → 返回 `{score, correct, total, wrong:[...], points:{earned,detail}, checkin:{done,streak}}`。

**正确率口径**：`correct / total`；语文按题计（字题+古诗题）。

### 5.3 积分（`points.py`）

```
单科完成(正确率≥60%) +10
单科优秀(≥90%)      +5
三科全完成(打卡)     +20
连击里程碑 3/7/14/30/100 → +10/30/60/150/500（当日一次性）
错题重练答对 +2/题（日上限 20）
日上限 100（settings 可改）
```

实现：`earn(child, delta, reason, ref)` 内做上限裁剪并写 `points_ledger` + `balance_after`。

**连击**：`streak = 昨日 checkin.streak + 1`，昨日无打卡则重置为 1；家长补卡不计连击。

### 5.4 SRS（`srs.py`）

阶段 0-5 → 间隔 `[1,2,4,7,15,30]` 天。答对 `stage+1`（上限 5），答错 `stage=max(0,stage-1)` 且 `next_date=明天`。古诗通过后进入 7 天档。

**`item_id` 必须是题库主键。** v1.8 之前存的是「当天第几题」，结果第二天复习取回的是库里 id=1、2、3 的字，跟孩子真正学过的东西完全无关；同时 `learned_ids` 也被污染，学过的字照样被当成新字重复出。现在 payload 里每道题都带 `ref_id`，落库统一用它。

只有 `char / word / poem` 进复习队列（`srs.SRS_KINDS`），数学每天现生成、没有稳定身份，记了也用不上。`srs_enabled` 关掉时 `due_items` 返回空、`learned_ids` 返回空集，出题退回全库随机。

### 5.5 数学出题引擎（`mathgen.py`）

注册表模式：

```python
@register("mul_multi_digit_by_1")
def _(p, rnd):  # p 来自 math_rule.params_json
    a = rnd.randint(p["a_min"], p["a_max"])
    b = rnd.randint(p["b_min"], p["b_max"])
    return {"stem": f"{a} × {b} =", "answer": a * b, "topic": "多位数乘一位数"}
```

内置 generator 覆盖 1-6 年级：20 以内加减、表内乘除、有余数除法、万以内加减、多位数×一位数、两位数÷一位数、三位数×两位数、除数是两位数、小数加减乘除、同分母分数加减、百分数互化等，共 **30+ 个**。`params_json` 允许家长在后台调区间/是否进位，并"预览 5 道"验证。

约定：结果非负、整除优先、避免除数为 0、避免超纲（三年级不出现分数）。

### 5.6 数据一致性

- 任务生成与提交在单个事务内完成；`checkin` 与 `points_ledger` 写入失败则回滚。
- 同一任务重复提交：以 `daily_task.status == done` 判定，返回既有结果，不重复计分。
- 积分冲正：`POST /admin/points/adjust` 写负数流水，禁止改历史。

## 7. 编码规范

- 后端：PEP8 + 类型注解；Blueprint 只做参数校验与序列化，业务在 `services/`；禁止裸 SQL；所有写操作显式 `db.session.commit()`；`db.create_all()` 仅用于首次初始化，后续用 Alembic。
- 前端：TS strict；组件函数式 + hooks；一个页面一个文件，超过 300 行拆分；样式只用 Tailwind（不写行内 style，动画除外）；禁止 `any`。
- 命名：DB 蛇形、API 驼峰（响应体）、组件大驼峰、文件 kebab-case。
- 提交：`feat(scope): 描述` / `fix(scope): 描述`。
- 每个接口必须有对应前端调用与错误提示；不做"预留但不通"的按钮。

## 8. 安全与运维

- 密码 bcrypt；JWT 7 天；后台接口全部 `@jwt_required()`。
- 客户端无鉴权但仅限内网；无个人信息上传；录音不出浏览器。
- 启动时若无 `db.sqlite` 则建表 + seed。
- 每日首启自动 `backups/db-YYYYMMDD.sqlite`（保留最近 7 份）。
- `.env`：`SECRET_KEY / ADMIN_USERNAME / ADMIN_PASSWORD / PORT / DATA_DIR`。

## 10. AI 辅助录入（v1.1）

### 10.1 设计取舍

题库录入是这类产品最大的隐性工作量。相比「让家长一条条手填」，更现实的做法是：**家长只提供最少的锚点信息（一个字、一个年级），其余字段交给模型**。

三个约束决定了实现方式：

1. **不能在前端调模型**：API Key 会暴露在浏览器里，且客户端无鉴权。所有请求走后端 `services/ai.py`。
2. **生成结果必须可校验**：模型会编字段、编出题器、把答案写成「60 支」。所以每类生成都有后端清洗函数，字段白名单 + 类型收敛 + 答案只留数字，不合格条目直接丢弃（而不是报错让用户重试）。
3. **不能重复**：把库里已有的标题/单词/句子作为 `exclude` 传给模型，入库时再走一次唯一性检查，双保险。

### 10.2 协议

`POST {base_url}/chat/completions`，`Authorization: Bearer <key>`，`response_format: {"type": "json_object"}`。
DeepSeek 与 OpenAI 兼容，所以 `ai_base_url` 填自建代理也能用。响应解析容忍 Markdown 代码块包裹。

### 10.3 生成类型与字段约定

| kind | 输入 | 输出字段 | 后端校验 |
|---|---|---|---|
| `char` | 单个汉字 | pinyin / radical / strokes / structure / words / sentence | 笔画转 int，组词转 JSON 数组 |
| `poem` | 年级、学期、数量、已有标题 | title / author / dynasty / genre / content / translation / notes / appreciation | 正文按行规范化，标题去重 |
| `word` | 年级、学期、数量、已有单词 | word / phonetic / pos / meaning / example / example_cn / kind | pos 归一化成 n./v./adj. 等，音标补斜杠 |
| `sentence` | 年级、学期、数量 | en / cn / key_words / phonetic_tip | 句子去重 |
| `math_rule` | 年级、学期、可用出题器清单 | name / generator / params / level | generator 必须在 `mathgen.GENERATORS` 内，params 必须是对象，level 归一成 5 档（出题比例由等级决定，不再有权重） |
| `math_question` | 年级、学期、数量、知识点 | stem / answer / unit / topic / level / solution | answer 只保留数字和 `/`、`.`，单位拆到 unit；level 归一成 5 档 |

### 10.4 前端交互

- 识字库：编辑弹窗内「AI 补全」，读当前 `char` 字段回填其余字段，不自动保存。
- 其它题库：列表页「AI 生成」，弹窗选年级/学期/数量/补充要求 → 后端出数据 → 前端逐条 POST 到原有 CRUD 接口 → 统计「新增 N 条 / 跳过 M 条」。
- 未配置 Key 时按钮可点但直接提示去设置，不做「点了没反应」。

### 10.5 安全

- `ai_api_key` 在 `settings.SECRET_KEYS` 里，`GET /admin/settings` 只返回 `ai_api_key_masked`（`sk-m••••••••6789`）和 `ai_api_key_set`。
- `PUT` 时字段留空或传回掩码视为「不修改」，避免前端把掩码写回数据库。
- 数据出网只包含年级、学期和已有词条列表，不含孩子姓名、学习记录等个人信息。

## 11. v1.2 变更：取消启停用、可选年级、AI 调用可观测

### 11.1 取消「启用/停用」

原设计把 `enabled` 当软删除用。实际使用中它带来两个问题：家长要记住「停用过的题不会出」，而且列表里一列状态没什么信息量。现在改为：

- 所有表去掉 `enabled` 列（grade / child / reward / 三科题库）。
- 删除就是物理删除，`DELETE` 直接 `db.session.delete()`；批量删除是一条 `DELETE ... WHERE id IN (...)`。
- 旧库升级由 `seed._drop_legacy_enabled_columns()` 处理：启动时检查 `PRAGMA table_info`，有就 `ALTER TABLE ... DROP COLUMN enabled`（SQLite ≥ 3.35），并写入 `data_version = 3`。
- 音标库仍限制「只能编辑」（48 个内置项，删了重启会被 seed 补回来），这是唯一保留的写限制。

### 11.2 语文/英语题库的年级学期（v1.7 已彻底移除）

v1.2 曾把年级学期做成「可选」——不填即通用条目，取题时 `(grade_id = 孩子年级 OR IS NULL) AND (term = 孩子学期 OR '')`。实践下来这套「可选」只会让人纠结填不填，而家长的真实诉求是：语文英语别管年级，全库随机；数学必须严格按年级学期。v1.7 直接把四张表的 `grade_id` / `term` 删掉，详见第 13 章。

### 11.3 唯一性约束

`char`（汉字）、`poem.title`（标题）、`english_word.word`（忽略大小写）在写入时查重：

- 不建唯一索引（SQLite 改动索引需要重建表，且家长可能想临时保留两条同名不同年级的记录），只在 `_register_bank` 的 create/update 里查一次。
- 更新时排除自身（`model.id != row.id`），否则保存其它字段会被判重复。
- 冲突返回 `409 CONFLICT`，前端直接 toast 后端文案（`「晨」已存在，不能重复添加`）。

### 11.4 思考模式开关

DeepSeek 的 `/chat/completions` 不传参数时**默认开启思考**，因此「默认关闭」必须在请求里显式下发：

```json
{"model": "deepseek-flash", "thinking": {"type": "disabled"}}
```

- `setting.ai_thinking` 默认 `false`，开启后下发 `{"type": "enabled"}`。
- 只对 `provider == deepseek` 下发该字段，避免自建代理/其它兼容实现因未知参数 400。
- 思考模式下 `temperature` 不生效、`max_tokens` 默认抬到 64K，题库生成这类结构化抽取任务关掉更快更省。

### 11.5 调用流水 `ai_call_log`

字段：`created_at / model / prompt / input_tokens / output_tokens / ok`。

- `prompt` 存用户侧提示词（system prompt 是固定样板，不重复存），截断 20000 字符。
- 从响应 `usage.prompt_tokens / usage.completion_tokens` 取值；请求失败也写一条（token 记 0、`ok=false`），便于区分「报错」和「没调用」。
- `GET /admin/ai/calls` 返回分页 + `total_calls / total_input_tokens / total_output_tokens`；`DELETE /admin/ai/calls` 清空。
- 写日志包在 try/except 里，失败只回滚日志本身，不影响生成主流程。

### 11.6 「单元」字段已移除（v1.4）

`chinese_char.unit`、`english_word.unit`、`english_sentence.unit` 原本只用于排序与展示，既没有「当前第几单元」的进度概念，也无法真正按单元控制出题范围，属于半成品字段，v1.4 直接删掉：

- 三张表的 `unit` 列通过 `data_version = 4` 的幂等迁移 `ALTER TABLE … DROP COLUMN unit` 移除（SQLite ≥ 3.35）。
- `math_question.unit` **保留**，它是答案单位（元/个/米），判分与题目展示都要用。
- 排序改为 `ORDER BY grade_id, term, sort_order`；后台 `?unit=` 筛选、AI 提示词里的 `context.unit`、前端列与表单里的「单元」一并删除。

### 11.7 AI 生成的去重范围与「补充要求」

v1.4 修掉两个真实问题：

**1）去重范围必须与唯一性校验一致。** 古诗按标题、单词按词、句子按英文全库唯一（不区分年级学期），但 `/admin/ai/suggest` 早期用「当前年级」过滤已有数据再交给模型。结果：选四年级时模型看不到一年级的《静夜思》，生成了 5 首里有 4 首在入库时被 409 拒绝。现在 `_existing_for_ai()` 一律取**全库**（诗 300 / 词 500 / 句 200 / 应用题 60），与 `_duplicate()` 的判断口径对齐。

**2）「补充要求」要真正进提示词。** 前端一直把 `context.requirement` 传给后端，但只有 `math_rule` 用了它。现在 `ai._extra_line(context)` 统一生成一段

```
家长的补充要求（在不违反下面 JSON 格式与条数要求的前提下优先满足）：<原文>
```

注入到汉字、古诗、单词、句子、应用题、出题规则六类提示词的开头附近。

同时把「条数」写死进提示词：`必须输出恰好 N 个，一首都不能少` + `items 里必须有 N 个元素`，并把 `max_tokens` 改成随数量增长（如古诗 `max(3000, 400 × count)`），避免要 10 首只回 5 首。

### 11.8 「排序」字段已移除（v1.5）

家长反馈不该让人手填排序号。v1.5 把所有 `sort_order` 删掉，`data_version = 5`，启动时 `_drop_legacy_sort_columns()` 对 9 张表做 `ALTER TABLE … DROP COLUMN sort_order`：
`chinese_char / poem / english_word / english_sentence / english_phoneme / math_rule / math_question / grade / reward`。

排序规则改为固定策略，不再有"排序"概念：

| 列表 | 排序 | 理由 |
|---|---|---|
| 题库（识字、古诗、单词、句子、音标、出题规则、应用题） | `created_at DESC, id DESC` | 最近录入的在最上面，刚用 AI 生成/手工加的立刻能看到 |
| 年级 | `id ASC` | 年级是学段语义顺序（一年级→高三），倒排会让下拉框从高三开始 |
| 奖励 | `id ASC` | 保持家长建奖励时的顺序，孩子端再按 `cost` 排 |

同一秒创建的多条记录 `created_at` 相同，用 `id DESC` 兜底保证翻页稳定。

取题侧（`taskgen`）不受影响：语文、英语从全库随机抽（v1.7 起不再有年级过滤），数学按年级学期精确匹配。**列表是倒序看的，孩子抽到的题是随机的**，两者互不干扰。

`models/base.py` 里只服务 `sort_order` 的 `order_by_sort()` 一并删除。

## 12. 内置题库导入（v1.6）

### 12.1 为什么要做

家长的原话是「不希望一个个维护」。AI 生成能批量出题，但仍要人点、要花钱、要联网校验；而小学识字表和课内古诗本身就是**公开且固定**的数据，没必要让模型重造一遍。所以直接把两份数据包放进仓库，后台点一下就完事。

### 12.2 数据包

| 文件 | 内容 | 规模 |
|---|---|---|
| `api/app/seed/data/chars_primary.json` | 汉字、拼音、部首、笔画、结构、组词、年级 | 2176 字，399 KB |
| `api/app/seed/data/poems_primary.json` | 标题、作者、朝代、体裁、正文、年级、学期 | 112 首，35 KB |

两份都是**离线产物**，随仓库分发。正常使用不需要联网，也不需要 Python 之外的工具。

### 12.3 数据来源与清洗

**汉字**（`scripts/build_chars.py`）：

| 字段 | 来源 | 说明 |
|---|---|---|
| 汉字 + 年级 | 小学常用汉字生字表 | 一年级在静态 HTML 里，二至六年级在页面 JS 变量里，两种都要抓 |
| 拼音 | Unihan `kMandarin` | 覆盖率 100%，带声调 |
| 笔画 | Unihan `kTotalStrokes` | 取第一个值（部分地区字形笔画数不同） |
| 部首 | Unihan `kRSUnicode` | 编号 → Kangxi Radicals 区块 → NFKC 归一 → 简繁映射 |
| 结构 | CJKVI IDS | 看构形符首位：⿰⿲ 左右、⿱⿳ 上下、⿴ 全包围、⿵⿶⿷⿸⿹⿺ 半包围 |
| 组词 | 统编教材词语表 + 12 册课文语料 + CC-CEDICT | 教材里出现过的词优先，CC-CEDICT 兜底 |

踩过的三个坑，都写进了构建脚本的注释里：

1. **部首码位不是汉字**。`kRSUnicode` 给的是 1-214 编号，映射到 Kangxi Radicals（U+2F00 起）得到的是 `⽕`（U+2F55）而不是 `火`（U+706B），直接和本字比较永远不相等。要先 NFKC 归一，再做简繁映射（`馬`→`马`、`艸`→`艹`、`辵`→`辶`）。
2. **部首编号带撇号**。简化部首写作 `149'.8`，`int("149'")` 会抛异常，得先 `re.sub(r"[^0-9]", "", ...)`。
3. **IDS 会把独体字拆成部件**。`火 = ⿱八人`、`四 = ⿴囗儿`、`云 = ⿱二厶`，按构形符判会得出「火是上下结构」这种明显错误。三条规则依次兜底：
   - 部首就是本字 → 独体（214 个部首字天然是独体字）
   - 分解出的末级部件全是笔画 → 独体（`二`、`三`、`王`）
   - 笔画 ≤ 4 且判定为上下/全包围 → 独体（4 画以内没有真正的上下结构字）
   - 再加一份 `SOLO_CHARS` 手写表兜住「天、末、本、西、南、太、尤」这类指事字

**古诗**（`scripts/build_poems.py`）：硬编码 112 首，按教材顺序、年级学期分组，正文按句分行。标题全库唯一，所以教材里两首同名的《绝句》《凉州词》加了首句括注（`绝句（两个黄鹂鸣翠柳）`）。

### 12.4 导入逻辑

`app/services/bank_import.py`：

- `preview()` 返回 `{total, available, existing}`，后台据此显示「还可导入 N 条」，为 0 时按钮禁用
- `import_chars()` / `import_poems()` **幂等**：先取全库已有的汉字/标题做集合，逐条比对，已存在的跳过
- 不覆盖已有记录 —— 家长改过的拼音、组词、译文不会被数据包冲掉
- **倒序写入**：`add_all` 一次提交，所有记录 `created_at` 相同，列表按 `id DESC` 排就会变成「六年级在最前」。倒序遍历后 id 恰好回到教材顺序，打开就是一年级第一课
- 不写 `grade_id` / `term`（v1.7 起这两列已从题库表删除），数据包里的年级只用于保持教材顺序

接口两个，都要求登录：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/bank/builtin` | 内置题库概况 |
| POST | `/api/v1/admin/bank/import` | body `{"kinds":["chars","poems"]}`，返回各类 `{created, skipped, total}` |

实测 2158 字 + 104 首一把写入 0.05 秒，重复调用全部跳过。

### 12.5 学期为什么不再写入

生字表只按年级分段，教材才分上下册。硬把字平分到两学期会凭空造出「这学期学这些字」的错误信息。v1.7 之后语文题库整体不关联年级学期，这个纠结直接消失：导入只写字形信息，孩子每天从全库随机抽。数据包里的 `grade` / `term` 字段保留，仅用于导入时的排列顺序（一年级在前）。

## 13. v1.7 变更：年级内置、语文英语脱离年级学期、数学严格匹配

### 13.1 年级内置只读

年级从「可维护的数据」变成「内置常量」：

- `seed.GRADES` 只保留 9 条：一年级~六年级、初一~初三，**去掉高中**（暂不需要，也避免下拉框里出现用不上的选项）。
- `seed._seed_grades()` 每次启动做一次同步：缺的补上；多的（旧库的 3 个高中）先清引用（`child.grade_id` 置空、删掉挂在该年级的数学规则与应用题）再删除。
- 后台删掉 `POST/PUT/DELETE /admin/grades`，只留 `GET /admin/grades` 给下拉框用；前端删除「年级管理」页面与路由，导航里的「档案」分组一并取消，孩子管理移到「系统」下（系统 → 孩子管理 / 系统设置）。

注意：**初中目前没有出题规则**。内置的 37 条数学规则只覆盖小学 1-6 年级（现有出题器都是小学口算：整数、小数、分数、比）。选初一~初三的孩子，数学只剩手录应用题可出，口算部分为空。需要的话得补初中出题器（负数、有理数、方程、根式等），这是独立工作量。

### 13.2 语文、英语题库不再关联年级学期

- 模型层：`chinese_char` / `poem` / `english_word` / `english_sentence` 删除 `grade_id`、`term` 两列；`math_rule` / `math_question` 保留。
- 迁移 `data_version = 6`：`seed._drop_legacy_bank_grade_columns()`。
- 后台：题库字段白名单、`/admin/chars` 等接口的返回不再有年级学期；前端四张表去掉「年级学期」列、筛选框与表单字段；AI 生成弹窗对语文/英语不再显示年级学期，也不往提示词里传。
- 导入：`bank_import` 不再按名称反查 `grade_id`，只写字形/文本内容。

### 13.3 取题：语文英语随机、数学严格

`taskgen` 里的 `_scope()`（按年级学期过滤）被两个函数替代：

- `_pick_unlearned(model, learned, n, rng)`：全库随机取未学过的 N 条
- `_pick_learned(model, learned, used, n, rng)`：复习池不足时从学过的里随机补

| 科目 | 取题 | 说明 |
|---|---|---|
| 语文识字 | `_pick_unlearned(ChineseChar, ...)` | 2176 字全库随机；复习仍走 `srs.due_items()` |
| 古诗 | `rng.choice(fresh or pool)` | 没背过的优先，全库随机 |
| 英语单词 | `_pick_unlearned(EnglishWord, ...)` | 全库随机 |
| 英语句子 / 音标 | `rng.choice(pool)` | 全库随机 |
| 数学口算 | `MathRule.filter_by(grade_id=child.grade_id, term=child.term)` | **严格同年级同学期**；仅当该学期一条规则都没配时，才退到本年级其他学期 |
| 数学应用题 | `MathQuestion.filter_by(grade_id, term)` | 本来就严格 |

选项池（拼音干扰项、释义干扰项、组词干扰项）也改成全库取样并去重，题库变大后干扰项质量反而更好。

代价要说清楚：语文英语不跟年级走之后，三年级孩子可能抽到六年级的字词。这是「随机、不维护」换来的特性，不是 bug；想控制难度就在题库上加「等级」而不是恢复年级——已于 v1.10 落地，见 §13.6。

### 13.4 落地时踩的坑

1. **SQLite 不能 `DROP COLUMN` 外键列**。`grade_id` 带 `FOREIGN KEY(grade_id) REFERENCES grade(id)`，直接 `ALTER TABLE ... DROP COLUMN grade_id` 报 `error in table ... after drop column: unknown column "grade_id" in foreign key definition`。改为重建表：`ALTER TABLE t RENAME TO t__old` → 按原 DDL 去掉目标列和外键行 → `CREATE TABLE` → 拷数据 → `DROP TABLE t__old`。见 `seed._rebuild_table_without()`。
2. **删列后 DDL 残留尾逗号**。原 DDL 是每行一列、最后一列不带逗号；删掉的正好是最后一列（或外键行）时，前一行会留下 `,` 紧跟 `)`，`CREATE TABLE` 报 `near ")"` 语法错误。用 `re.sub(r",\s*\)\s*$", "\n)", ddl)` 兜住。
3. **`_build_sentence(child, rng, pool)` 的 `pool` 参数**在改成全库随机后失效，函数内部自己查库，调用处记得同步改签名，否则 `NameError: name 'pool' is not defined`。

## 14. v1.8 变更：复习与错题记录真实主键、错题重练闭环

### 14.1 病根

`srs_item` 和 `wrong_item` 的 `item_id` 存的是 payload 里的 `item_id`，而它是**当天第几题**（1、2、3…）。于是：

- 第一天学「扯/屈/作/接/拣」（题库 id 235/412/1020/1704/1817），`srs_item` 记的是 1~5；
- 第二天 `due_items` 返回 1~5，`ChineseChar.query.get(1..5)` 取回的是「晨/绒/球/汉/艳」——**复习内容和学过的东西毫无关系**；
- 反过来 `learned_ids` 返回 `{1..5}`，`_pick_unlearned` 拿它比 `ChineseChar.id`，真正学过的字一个都没被排除，改天还会当新字抽出来，而库里 1-5 号字被永久拉黑；
- 错题本唯一键是 `(child, subject, item_type, item_id)`，不同天不同题目的「第 1 题」会被合并成一条：`wrong_count` 虚增、`ref_text` 被后一天覆盖。数学最严重，永远只有 1~20 号。

### 14.2 改法

1. **payload 每道题带 `ref_id`**：汉字 / 单词 / 古诗 / 句子 / 音标 / 应用题都是题库主键；数学计算题 `ref_id` 为 `None`。
2. **统一取键函数** `taskgen.item_key(item)`：有 `ref_id` 用主键，没有就 `md5(kind + topic)`，保证同一知识点拿到同一个编号。
3. **`srs.record / due_items / learned_ids` 全部用主键**，且只处理 `char / word / poem`（`srs.SRS_KINDS`）。数学不进复习队列。
4. **错题按 `(kind, key)` 归并**，同一天同一知识点出好几道只记一次——否则「错 10 次」其实只是同一张卷子错了 10 道同类题。
5. `data_version = 7`：`seed._add_wrong_snapshot_column()` 给 `wrong_item` 加 `snapshot_json`，并清空 `srs_item` / `wrong_item`（旧记录全是错的，留着只会继续污染）。

### 14.3 错题重练

- `taskgen._retry_items()` 从 `wrong_item`（`mastered=False`）按 `wrong_count` 倒序取候选，在候选里 `shuffle` 后取前 `RETRY_LIMIT`（固定 2）条，用 `snapshot_json` 还原成题目，打上 `retry: True`。
- 插在当天任务最前面；若当天本来就会复习到同一道题，**用重练版本替换掉**普通版本，不重复出。
- 古诗（`RETRY_SKIP_KINDS`）不进重练队列，它走的是独立的背诵流程，塞回选择题会很怪。
- 答对一次 `correct_streak+1`，累计 2 次 `mastered=True`，自动移出重练池；答错清零。
- 积分：重练答对给 `point_wrong_fix`（默认 2/题），受 `point_wrong_fix_cap`（默认 20/天）限制，再叠加 `daily_point_cap` 总上限。`points.earned_by_reason()` 负责算当天该来源已拿多少分。

### 14.4 让开关真正生效

| 键 | 之前 | 现在 |
|---|---|---|
| `srs_enabled` | 只有默认值，没人读 | 关掉后不出复习题、`learned_ids` 返回空集，全库随机 |
| `instant_feedback` | 只有默认值，没人读 | `/client/task/answer` 返回 `{correct: null, deferred: true}`，前端直接进下一题，交卷才看结果 |
| `audio_enabled` | 只有默认值，没人读 | 新增 `/client/prefs` 下发，客户端隐藏「听读音 / 播放」按钮 |
| `point_wrong_fix` / `_cap` | 只有默认值，没人读 | 重练答对按条给分并受日上限约束 |

### 14.5 验证

临时库跑三天：第一天全错 → `srs_item.item_id` 与汉字主键完全一致；第二天复习到的正是第一天那 5 个字，且前 2 道是重练题；第二天答对后 `correct_streak=1`，第三天再对 `mastered=True`。数学错题按知识点聚合成 4 条，第二天重练 2 条；`srs_item` 里没有数学记录。

### 14.6 没做的事

- 初中（七至九年级）仍然没有出题规则，家长选了初中的话口算题为空。
- 错题本只有「看」和「自动重练」，没有「手动挑几道单独练」的入口。

## 15. 多值字段改用标签输入（v1.9）

识字库「组词」、音标库「例词」原本是「逗号分隔的文本框」，存 `words_json` / `examples_json`，家长填的时候常漏逗号或把两个词粘成一个。改成标签输入：

### 17. 题库等级（难度）与按比例出题

家长诉求：语数英题库都要能标难度，出题时按「容易 20% / 较易 30% / 中等 30% / 较难 15% / 困难 5%」配比。

**字段**：`chinese_char / poem / english_word / english_sentence / math_rule / math_question` 六张表统一加 `level VARCHAR(8) DEFAULT '中等'`；`math_question` 原来的 `difficulty(1-3)` 直接删掉（两个难度字段会打架）。音标库不加——48 个音标是基础符号，不分难易。

**常量**：`services/level.py` 里只有一份定义。

```python
LEVELS  = ("容易", "较易", "中等", "较难", "困难")
RATIOS  = (0.20, 0.30, 0.30, 0.15, 0.05)
GRADE_LEVEL = {1: "容易", 2: "容易", 3: "较易", 4: "中等", 5: "较难", 6: "困难"}
```

- `allocate(n)`：最大余数法把 n 道题拆到 5 档，合计一定等于 n（5 道 → 1/2/1/1/0，20 道 → 4/6/6/3/1）。
- `split(pool, n, rng)`：从候选池里按配额取，**某档不够就从未选中的任意档补**，所以不会因为题库偏科而少题、更不会抽到重复条目。
- `pick_one(pool, rng)`：每天只出 1 道的题（古诗、英语句子）按比例加权选档，再在档内随机。

**出题接入点**：

| 位置 | 改动 |
|---|---|
| `taskgen._pick_unlearned()` | 语文新字、英语新词改走 `level.split()`；复习题不按比例（该复习的必须复习） |
| `taskgen._build_poem()` | 未学过的诗池按 `pick_one()` 选档 |
| `taskgen._build_sentence()` | 同上 |
| `taskgen._build_math()` | 应用题按比例抽；计算题把配额分给各档规则，某档没规则才回补，`_gen_rule_items()` 负责按权重出题 |

数学的配额有个天然限制：出题规则严格按「年级 + 学期」过滤，而规则等级又是按年级折算的，所以同一学期内往往全在一个档（三年级上全「较易」）。这时配额自动回补，20 题照样凑齐，只是难度分布由该年级的规则决定。想在一学期内做难度梯度，就在「出题规则」里把同一知识点的几档规则分开建（等级可在后台改）。

**导入映射**：`bank_import` 读数据包里的 `grade`（教材年级），按 `GRADE_LEVEL` 折算成等级写入：

| 数据包 grade | 1、2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|
| level | 容易 | 较易 | 中等 | 较难 | 困难 |

导入仍是幂等的，已存在的跳过，不会冲掉家长改过的等级。「系统设置 → 内置题库」会先展示数据包折算后的等级分布（容易 974 / 较易 444 / 中等 287 / 较难 289 / 困难 182）。

**AI**：六类生成（识字/古诗/单词/句子/出题规则/应用题）的提示词都注入 `_LEVEL_GUIDE` + 批次配额（`_level_quota_line(count)`），模型返回的 `level` 一律走 `level.normalize()` 兜底为「中等」。单个补全（汉字、单词、句子）也会带上等级。

**迁移**：`data_version=8`，`_add_level_columns()` 给旧库补列、并按年级回填 `math_rule.level`。`ensure_seed()` 里 `_run_migrations()` 被提到 seed 之前——以前放在最后，导致新列还没加上 seed 就去查它（`no such column: math_rule.level`）。

## 17. v1.11 变更：古诗背诵录音、数学不留退路、全科断点续做

三条改动都指向同一件事：**别让孩子能混过去，也别让家长看不到过程**。

### 17.1 古诗不再出题，改成「听读 → 背诵录音」

原先 `_build_poem()` 随机出「选下一句 / 挖空填字」，而整首诗就印在上方卡片上——问其中一句等于白给，孩子扫一眼就能选对，这道题不产生任何信息。现在古诗只产出一种题型：

```python
return {**base, "type": "recite", "stem": f"背一背《{poem.title}》", "answer": "__recited__"}
```

- **「跟读」标签删掉**：跟读录音只存本地、孩子也基本不用；真正有意义的是「能不能背着说出来」。
- **「整首朗读」搬进听读标签**（`poem-player.tsx`），标签栏只剩「听读 / 背诵」两项。
- 切到「背诵」标签时正文**立刻打码**：每行加 `blur-[7px] select-none`，同时 `aria-hidden` 并关掉逐句点读，避免朗读帮忙作弊。
- 录完可回放、可重录，确认后 `POST /client/poem/recite`（multipart，单文件上限 8MB）。

服务端这一环刻意做得很轻：**不判分、不匹配答案、不进错题本**，但一定有留存——

| 表 | 内容 |
|---|---|
| `recitation` | 孩子、日期、诗名、时长、文件大小、`uploads/recite/YYYY-MM/随机名.webm` |
| `study_record` | 一条「背诵录音 / 未背诵」的流水，**上传了录音 `is_correct` 就是 True** |
| `task_answer` | 按 `__recited__` 标记这道题已处理，续做时不会出现在剩余清单里 |

**背诵的结果只有一个布尔值：交了录音就是对，没交就是错**，不存在中间态。

最早这里写的是 NULL（`sqlalchemy.null()`），本意是「不判对错」，但学习记录页按 `r.is_correct ? '对' : '错'` 渲染，NULL 会被引擎判成「错」——孩子明明背了，后台却显示红字。这个字段承载的是「今天这件事做没做完」，不是「背得好不好」，后者交给家长听录音判断，不该落在数据表里。旧数据由迁移 v10 `_fix_poem_record_result()` 回填：`user_answer` 不是「未背诵」的一律置 True。

| 渲染 | 条件 |
|---|---|
| 绿色「已背诵」 | `item_type == 'poem' && is_correct`，正确答案列显示「以录音为准」 |
| 黄色「未背诵」 | `item_type == 'poem' && !is_correct` |
| 绿「对」/ 红「错」 | 其余普通题 |

`taskgen.NO_SCORE_KINDS = ("poem",)` 是一条全局约定：这类题不计入总分（`count_scored()` 在 `daily_task.total` 落库时就算好了），也不走错题与积分，但复习队列仍会记一笔「今天背过」，隔一段时间还会再遇到这首诗——否则每天都可能随机到同一首。

> 踩坑（已废弃，留着提醒别再犯）：设计成 NULL 时写的是 `sqlalchemy.null()`——直接给 `None` 会被列的 `default=False` 顶回来。现在这个字段不再需要 NULL，反而说明一个道理：布尔列别用来表示「三态」，真有三态就单独加一个状态字段。

### 17.2 数学不再有「不会，跳过我」

`quiz.tsx` 里那行跳过链接加了 `!isMath` 条件。语文英语保留（错了可以在错题本里重做），数学必须交一个答案——答案错了才是对的错题，直接跳过等于把知识点掩盖掉。

### 17.3 全科断点续做

之前的进度只活在内层 ref 里：平板息屏、被叫去吃饭、手滑退出都能把做的一半抹掉。现在**每答一题就落到库里**：

```
POST /client/task/answer  →  submit.save_progress()  →  task_answer(task_id, item_id) 唯一约束 upsert
POST /client/task/start   →  answered[] / answered_count：已经答过的题
```

客户端用 `lib/resume.ts` 的 `resumeItems()` 把已答的剔掉，剩下的才是这次要练的：

- 题号显示 `第 3 / 10 题 · 接着上次`，页头写「上次做到第 2 题，今天还剩 8 题」。
- `/client/task/submit` 里 **`answer_map` 以服务端存档为准**，客户端传上来的只做覆盖。即使前端状态丢了（标签页被回收）也不会漏题。
- 全部答完但没来得及提交就退出？下次进入科目页时 `{list.length > 0 && remaining.length === 0}` 会自动补一次 `submit([])`，直接进结果页。**题库为空时不能走这条**，否则会把 0 题的任务标记完成。
- 语文要额外判断古诗有没有录过：`poemLeft = poemItem && !answeredIds.has(item_id)`，生字做完了但诗还没背，回来就直接进背诵页。

### 17.4 家长听得见

`GET /admin/recitations`（分页 + 按孩子/日期筛选）与 `GET /admin/recitations/<id>/audio`（`send_file`）都在 JWT 之下。`<audio>` 标签带不上自定义请求头，所以后台页面先把文件 `fetch` 成 blob 再播：

```ts
fetch(row.url, { headers: { Authorization: `Bearer ${getToken()}` } })
```

注意 `row.url` 后台返回的是**带 `/api/v1` 前缀**的完整路径，前端不要再拼一次前缀（拼了就是 `/api/v1/api/v1/...` → 404 → 显示「录音文件不在了」）。文件本身按 `DATA_DIR/uploads/recite/` 存放，库里只存相对路径，换机器拷目录即可；`checkin_void()` 作废某天时，连带删掉当天的 `task_answer` 与录音文件，避免孩子重做时还带着作废前的进度。

### 18. 题库检索：难度 / 词性 / 音标类型过滤，出题规则去掉权重

后台题库列表原来只有「关键词 + 年级 + 学期」三个条件，等级上线后没法按难度筛。改法是**通用过滤**，不写死某一库：

- `admin._filtered()` 遍历 `_FILTER_COLUMNS = ("level", "pos", "kind", "type", "category", "genre")`，模型上有这一列、且请求带了同名参数才加 `WHERE`。所以：
  - `chinese_char / poem / english_word / english_sentence / math_rule / math_question` 自动获得 `level` 过滤；
  - `english_phoneme` 没有 `level` 列 → 天然不支持难度过滤，只支持 `type=vowel|consonant`；
  - `english_word` 的 `pos` 过滤免费拿到。
- `all` / 空值忽略；`none` 匹配空串或 NULL。多个条件是与关系（`?level=容易&pos=n.`）。
- 前端 `BankConfig.filters?: FilterDef[]` 声明该库要显示哪些下拉，`name` 就直接作为查询参数，状态存在 `extra` 里并进 queryKey；`App.tsx` 给 `BankPage` 加了 `key={cfg.key}`，切库时筛选条件不会串库。

| 库 | 过滤器 |
|---|---|
| 识字库 / 古诗库 / 句子库 / 出题规则 / 应用题 | 等级 |
| 单词库 | 等级 + 词性 |
| 音标库 | 类型（元音 / 辅音） |

**出题规则去掉 `weight`**（`data_version=9`，`_drop_math_rule_weight()` 重建表删列）：一道题出多少完全由等级配额决定，同档规则等概率。留着权重会出现「配额说 6 道、权重又要求某条多出」两套逻辑打架，家长也看不懂该填几。种子数据、AI 生成的 `math_rule` 提示词、后台表单/列同步删掉。

顺带修了个会导致数学题变少的 bug：`_prepend_retries()` 用 `item_key()` 给「错题重练」和「今天本来要出的题」去重，而数学计算题的 `item_key` 是按**知识点**聚合的哈希（同一知识点共用一个编号），结果某个知识点有 1 道错题，当天这个知识点的所有题都被当成重复删掉——20 题会缩水成 10 题。现在数学改按题干去重（`_dedupe_key()`），语文/英语仍按 `ref_id`。
